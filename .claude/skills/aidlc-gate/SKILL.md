フェーズの境で点検し、通過したときだけ次へ進める。品質の判断はしない — 成果物の内容の承認は人の仕事で、ここは記録との整合の機械検査。

## 点検項目

対象フェーズは `aidlc-state.md` の進捗表から特定する。

1. **成果物の存在** — フェーズディレクトリに成果物があるか。「未着手」のまま次へ進もうとしていないか
2. **トレーサビリティ** — 成果物のファイル名が `audit.md` に現れるか。判断の記録なしに成果物が増えていないか
3. **孤立成果物** — audit にも進捗表にも言及のないファイルがフェーズディレクトリにないか(`.backup` は除外)
4. **成功条件と懸案** — その時点で確認できる成功条件に達成の記録(audit・report)があるか。再判断期限の過ぎた懸案が文書に残っていないか

## 判定

- **通過**: 進捗表の当該フェーズを「完了」に更新し、`audit.md` に 1 行追記(`gate pass <phase>`)する。`aidlc-docs/` が git 管理下にあるならチェックポイントとして同じメッセージでコミットする(管理外=`.git/info/exclude` 等で除外されている場合はコミットせずスキップ)。次のフェーズを提案する
- **停止**: 不足と孤立を一覧で報告して中断する。不足分を埋めてから再実行する。点検結果を歪めない(通るように書き換えない)
